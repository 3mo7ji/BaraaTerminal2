# R7Host — إصدار 2.0

تطبيق Android محلي لتشغيل لوحة BotDock باستخدام محرك Node.js مدمج، مع واجهة محسّنة وسجل يمكن نسخه أو مسحه.

## ما تم تحسينه

- تشغيل محرك Node.js داخل Foreground Service بدل خادم ملفات ثابتة فقط.
- تشغيل لوحة BotDock على `http://127.0.0.1:3000`، بما في ذلك Express ومسار تسجيل الدخول `/api/login`.
- إيقاف وتشغيل خادم اللوحة من دون محاولة إعادة تشغيل محرك Node.js نفسه. محرك Node.js يبقى في الخدمة، بينما يتم إيقاف/إعادة فتح منفذ لوحة BotDock.
- لا يتطلب زر الخلفية إيقاف الخادم؛ وظيفته فقط فتح إعدادات استثناء تحسين البطارية.
- اكتشاف مجلد BotDock المختار حتى لو كان داخل مجلد فرعي، ثم نسخ الملفات اللازمة إلى مساحة التطبيق الخاصة.
- سجل موحد مع زري «نسخ السجل» و«مسح».
- إضافة INTERNET وWake Lock والإشعارات وخدمة أمامية.
- واجهة داكنة جديدة، حالة تشغيل فعلية من وحدة تحكم محلية، وتعطيل الأزرار أثناء تنفيذ الطلب.

## البناء عبر GitHub Actions

1. ارفع محتويات هذا المجلد إلى مستودع GitHub.
2. افتح تبويب Actions.
3. شغّل `Build R7Host APK` أو ادفع commit إلى فرع `main`.
4. افتح عملية البناء الناجحة ثم نزّل Artifact باسم `BaraaTerminal2-v2-debug-APK`.
5. ثبّت `app-debug.apk` على هاتف Android.
6. إذا رفض Android تثبيت الإصدار فوق النسخة القديمة بسبب اختلاف التوقيع، احذف النسخة القديمة أولًا ثم ثبّت الجديدة. مجلد BotDock الأصلي في «ملفاتي» لن يُحذف.

أثناء البناء، ينزّل GitHub Actions مكتبة Node.js for Mobile Apps v18.20.4 من إصدارها المنشور، ثم يضمّن مكتبات ARM64 وARMv7 وx86_64 ويثبت اعتمادات Express وAdmZip داخل التطبيق.

## طريقة الاستخدام

1. افتح التطبيق وامنحه إذن الإشعارات عند الطلب.
2. اضغط «اختيار مجلد BotDock» وحدد المجلد الذي يحتوي `server.js` ومجلد `public`.
3. اضغط «تشغيل BotDock».
4. عندما تصبح الحالة «يعمل الآن»، افتح `http://127.0.0.1:3000` من المتصفح أو زر «فتح لوحة التحكم».
5. زر «إيقاف الخادم» يوقف لوحة الويب، ويظل محرك Node.js الداخلي في وضع انتظار حتى يمكن تشغيل اللوحة مرة أخرى دون إعادة تحميل المحرك.
6. «إعداد السماح بالعمل في الخلفية» يفتح إعداد البطارية فقط ولا يوقف أو يشغّل الخادم.
7. استخدم «نسخ السجل» أو «مسح» في بطاقة السجل.

## قيود مهمة يجب معرفتها

- يستخدم هذا الإصدار Node.js Mobile v18.20.4. مشروع BotDock الأصلي يعلن في package.json أنه يحتاج Node.js 20 أو أحدث؛ لذلك لا يمكن اعتبار توافق كل أجزاء المشروع مضمونًا على هذا المحرك.
- Node.js Mobile لا يدعم `child_process` أو `cluster`. لهذا تعمل لوحة BotDock وواجهاتها وطلبات API، لكن تشغيل بوتات Discord كعمليات مستقلة غير متاح داخل هذا التطبيق. يعرض BotDock رسالة صريحة بدل ادعاء تشغيل البوت.
- لا يمكن تشغيل محرك Node.js المدمج أكثر من مرة داخل العملية نفسها. لذلك يبقى المحرك في الخدمة، وتتم عملية إيقاف/تشغيل خادم الويب داخله؛ إيقاف الويب لا يعني إنهاء محرك Node نفسه.
- السماح باستثناء تحسين البطارية يقلل احتمال الإيقاف لكنه لا يضمن تشغيلًا دائمًا 24/7؛ نظام Android والشركة المصنّعة قد يوقفان العمليات.
- لوحة التحكم مربوطة على `127.0.0.1` لهذا البناء، أي للاستخدام على الهاتف نفسه فقط. لا تكشفها على شبكة عامة.
- اعتمادات Express وAdmZip مضمنة في ملفات التطبيق؛ لا يحتاج المستخدم إلى `npm install` داخل مجلد Android المشترك.
