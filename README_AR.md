# R7Host 3.1 — إدارة بوتات Discord على Android

R7Host تطبيق Android محلي لإدارة وتشغيل ما يصل إلى **5 بوتات Discord** من واجهة عربية داكنة. يحتفظ التطبيق بملفات البوتات والإعدادات داخل مساحة التطبيق الخاصة، ويشغّل كل بوت JavaScript في Worker Thread مستقل داخل محرك Node.js المدمج.

> **هذه نسخة مصدر جاهزة للبناء عبر GitHub Actions وليست APK جاهزًا.** يحتاج البناء إلى تنزيل مكتبة Node.js Mobile وAndroid SDK/NDK وCMake أثناء تشغيل Workflow.

## ما الذي بُني في الإصدار 3؟

- واجهة R7Host جديدة: لوحة رئيسية، إحصاءات، إدارة السيرفرات، صفحة تفاصيل، تبويبات السجلات والملفات وإعدادات التشغيل.
- إنشاء عدة سيرفرات/مشاريع بوتات، مع حد إجمالي قدره 5.
- رفع ZIP وفك الضغط مع رفض المسارات الخطرة، وحد حجم رفع 45 MB وحجم مفكوك 180 MB.
- مدير ملفات: تصفح المجلدات، إنشاء ملف/مجلد، فتح النصوص وتحريرها، حفظ، إعادة تسمية وحذف.
- تشغيل ملفات `.js` و`.cjs` و`.mjs` مباشرة.
- عامل Worker Thread مستقل لكل بوت، مع التقاط stdout/stderr في Console.
- إعادة تشغيل تلقائية عند التعطل: تدرّج في الانتظار، وبحد 5 محاولات خلال 10 دقائق لتفادي حلقات التشغيل المتكررة.
- حفظ حالة التشغيل المقصودة واستعادة البوتات عند إعادة تشغيل محرك R7Host.
- Android Foreground Service + إشعار دائم + PARTIAL_WAKE_LOCK، مع خيار طلب إعادة تشغيل R7Host بعد إعادة تشغيل الهاتف.
- مساعد R7 AI: تشخيص محلي مجاني لقواعد أخطاء شائعة، ومحادثة اختيارية مع مزود متوافق مع OpenAI Chat Completions.
- أوامر سريعة من المحادثة عند تحديد سيرفر: تشغيل، إيقاف، إعادة تشغيل، وتشغيل/إيقاف الكل بعد تأكيد المستخدم، بالإضافة إلى الاستعلام عن حالة جميع البوتات.
- مفتاح AI لا يُضمّن في المشروع؛ يمكن حفظ مفتاح خاص بك داخل مساحة التطبيق أو إزالته لاحقًا.
- ملفات المشاريع وبياناتها لا تُحذف عند تحديث ملفات التطبيق.

## طريقة بناء APK

1. ارفع محتويات مجلد `BaraaTerminal2` إلى مستودع GitHub على الفرع `main`.
2. افتح تبويب **Actions**.
3. شغّل Workflow باسم **Build R7Host APK** أو ادفع Commit إلى `main`.
4. بعد نجاح البناء، افتح العملية ونزّل Artifact باسم **R7Host-v3.1-debug-APK**.
5. فك ملف Artifact وثبّت `app-debug.apk` على هاتف Android.
6. في أول تشغيل، يعرض التطبيق رمز دخول من 8 أرقام. انسخه واحتفظ به ثم أدخله في شاشة الدخول.

### ما الذي يقوم به GitHub Actions؟

- يستخدم Java 17 وGradle 8.9.
- ينزّل Node.js Mobile v18.20.4 لمعماريات Android المحددة في المشروع.
- يثبت مكتبات الخادم المضمّنة: Express وAdmZip وdiscord.js v14.
- يجهّز Android SDK وNDK وCMake، ثم يبني APK ويرفعه كـ Artifact.

## الاستخدام

1. افتح R7Host، انسخ رمز الدخول الذي يظهر أول مرة، ثم سجّل الدخول.
2. اضغط **إنشاء سيرفر** واكتب اسمًا لمشروع البوت.
3. افتح السيرفر وارفع ZIP يحتوي ملفات مشروع البوت.
4. راجع تبويب **إعدادات التشغيل** وحدد ملف البداية، مثل `index.js` أو `bot.js`.
5. ضع متغيرات البيئة محليًا في حقل Startup، مثل `DISCORD_TOKEN=...`. لا ترسل التوكن في المحادثات أو السجلات ولا تضعه في مصدر عام.
6. اضغط تشغيل البوت، وتابع Console حتى تتأكد من نجاح تسجيل الدخول إلى Discord.
7. اترك R7Host يعمل في الخلفية. من الإعدادات يمكنك طلب استعادته بعد إعادة تشغيل الهاتف، وفتح إعدادات تحسين البطارية.

## تجهيز ملفات البوت ومكتبات npm

محرك Node.js Mobile لا يشغّل `child_process` ولا أوامر النظام، لذلك لا يستطيع تنفيذ `npm install` أو `npm run` كعمليات خارجية داخل الهاتف.

- مكتبة `discord.js` v14.21.0 مضمنة في R7Host، فلا تحتاج إلى تكرارها داخل ZIP إذا كان بوتك يستخدمها.
- إذا كان مشروعك يحتاج مكتبات إضافية، أرفق مجلد `node_modules` معها داخل ZIP بعد تجهيزها في بيئة Node.js متوافقة.
- يجب أن يكون ملف البداية موجودًا في ZIP، ويفضل أن يحتوي الجذر على `package.json` و`index.js` و`node_modules` عند الحاجة.
- استخدم ملف JavaScript مباشرًا كبداية؛ خيارات `npm start` وnpm scripts غير مدعومة في هذا المحرك.
- بعض الحزم التي تعتمد على إضافات Native أو أوامر النظام أو `child_process` لن تعمل. هذا ليس خطأ في ملفك، بل قيد في محرك الهاتف.

## كيف يعمل تشغيل البوتات؟

Node.js Mobile لا يوفّر وحدة `child_process` أو `cluster` على Android. لذلك لا يدّعي R7Host وجود عمليات نظام مستقلة. بدلًا من ذلك، يستخدم Worker Threads المتاحة في Node.js Mobile، بحيث يحصل كل بوت على عامل منفصل ومخرجات مستقلة ومراقبة وإعادة تشغيل من مدير R7Host.

هذا العزل **ليس مساويًا لعملية Linux مستقلة**: العوامل تشترك في عملية Android الرئيسية، ولا يمكنها تنفيذ أوامر shell. انهيار Native في العملية أو إغلاق Android للتطبيق قد يوقف جميع البوتات معًا. كما أن خمسة بوتات قد تستهلك ذاكرة وبطارية كثيرة؛ الحد الأقصى لا يعني أن كل هاتف قادر على تشغيل خمسة بوتات بسلاسة.

## هل يعمل 24/7؟

يستخدم التطبيق Foreground Service وإشعارًا مستمرًا وWake Lock لتقليل توقف المحرك في الخلفية. كما يمكن تفعيل استقبال BOOT_COMPLETED لاستعادة المحرك بعد إعادة تشغيل الجهاز.

**لا يمكن ضمان 24/7 على هاتف Android.** قد يوقف النظام أو الشركة المصنّعة التطبيق عند ضغط الذاكرة أو نفاد الطاقة، وقد لا يُسمح بإعادة التشغيل بعد Force Stop، كما يتوقف كل شيء عند إطفاء الهاتف أو انقطاع الإنترنت. إبقاء Wake Lock نشطًا قد يزيد استهلاك البطارية والحرارة. التشغيل المستمر الموثوق يحتاج جهازًا دائم التشغيل أو خادمًا خارجيًا.

## مساعد R7 AI

- التشخيص المحلي يعمل دون مفتاح API، ويبحث عن أنماط شائعة في سجلات الأخطاء.
- للردود التوليدية، أدخل رابط API متوافقًا مع Chat Completions واسم النموذج ومفتاحك الخاص.
- لا يتضمن المشروع مفتاحًا أو خدمة AI مدفوعة. لا توجد شبكة نموذج محلي كبيرة مدمجة داخل APK؛ الردود التوليدية تحتاج مزودًا خارجيًا. استخدام المزود الخارجي قد يترتب عليه حدود أو تكلفة حسب مزودك.
- عند إرسال سؤال مع تحديد سيرفر، تُرسل آخر أجزاء من سجل ذلك السيرفر إلى المزود الخارجي بعد محاولة إخفاء صيغ شائعة للتوكنات. لا تزال مراجعة السجلات قبل إرسالها مسؤوليتك؛ لا تضع الأسرار في الرسائل.
- لا ينفذ المساعد تعديلات برمجية أو أوامر نظام تلقائيًا. أوامر تشغيل/إيقاف محددة تتطلب تأكيدًا.

## الأمان والخصوصية

- خادم الويب مربوط على `127.0.0.1` ولا يفتح لوحة الإدارة على الإنترنت.
- رمز الدخول عشوائي من 8 أرقام، والجلسة تحفظ في ذاكرة الخادم.
- إعدادات البوت وملفاتها ومفتاح AI تُحفظ في مجلد التطبيق الخاص على Android. مفتاح AI لا يعود إلى واجهة المستخدم بعد الحفظ.
- لا ترفع ZIP من مصدر لا تثق به؛ تشغيل مشروع Node يعني تنفيذ كود ذلك المشروع داخل التطبيق.
- لا تضع Bot Token داخل كود عام أو ترسله لأي شخص. استخدم متغيرات البيئة في Startup.

## اختبارات أجريَت على المصدر

- فحص صياغة JavaScript باستخدام `node --check`.
- اختبار Worker Thread تجريبي: تشغيل ملف بوت في عامل، استقبال stdout، وكتابة ملف نسبي داخل مجلد البوت، ثم إنهاء العامل.
- لم يُبنَ APK في بيئة التأليف الحالية لعدم توفر Android SDK/NDK وGradle؛ GitHub Actions يتولى هذه الخطوة. يجب تثبيت الـ APK الناتج واختباره على الهاتف قبل اعتبار الاستضافة مستقرة.
